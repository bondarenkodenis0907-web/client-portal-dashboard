# Приёмка

Критерии сохраняются при рефакторинге. Локальные результаты — в [verification](evidence/verification.json); hosted и пилотная приёмка выполняются отдельно.

## Текущий цикл

- **Q01 — Чистый запуск тестовой среды.** Все 10 миграций и фактическая схема совпадают, без скрытых ручных предпосылок.
- **Q02 — Существующий SQL baseline.** 7 файлов / 200 SQL тестов PASS на чистой схеме.
- **Q03 — Существующий workflow клиента/staff.** Создать → назначить → обработать → закрыть → прочитать результат/историю
- **Q04 — Клиент A и B, прямой REST/API и UUID.** Чужие заявки/события/профили не читаются и не меняются; metadata не повышает роль
- **Q05 — Отозванный staff со старым JWT.** Следующая staff-операция запрещена; история/авторство сохранены
- **Q06 — Недопустимый переход/closed/неактивный assignee.** БД отклоняет без частичной записи и лишнего события
- **Q07 — Вход/выход/refresh/истёкшая сессия/две вкладки.** Cookie refresh корректен, защищённые страницы и данные недоступны без прав; ошибки не маскируются
- **Q08 — Неодобренный host, Preview и POST до Auth.** Отказ до refresh и обращений к рабочему Supabase; no-store; local bypass не работает в облаке
- **Q09 — Изолированный разрешённый staging.** Ref/ключи/env/network относятся только к staging; production ref отсутствует в его bundle и запросах
- **Q10 — Retired Netlify и активный Vercel.** Retired-проект подтверждён disabled/stopped; активный host защищён; произвольный 404 не считается изоляцией
- **Q11 — Существующий и неизвестный email recovery.** Generic ответ и отсутствие прямого раскрытия существования аккаунта; ошибки/лимиты проверены
- **Q12 — Scanner GET callback/confirm и reload.** VerifyOtp не вызывается, token не расходуется, нет authenticated reset формы до подтверждения
- **Q13 — Явный разрешённый POST и новый пароль.** Relative redirect сохраняет origin; новый вход работает; принятая политика завершения сессий соблюдена
- **Q14 — Replay/истёкший/неверный token.** Отказ без утечки деталей, внешнего redirect и частичного успеха
- **Q15 — Чужой Origin/Fetch Metadata, отсутствующие заголовки, malformed form.** Поведение соответствует принятой политике; безопасные 4xx/ошибки, без непредсказуемого 500
- **Q16 — Смена пароля удалась, signOut вернул error/сеть оборвалась.** UI не утверждает подтверждённый выход; безопасный путь завершения; секретов в логах нет
- **Q17 — Обычная текущая сессия открывает reset.** Поведение соответствует D04, а не неявному предположению recovery-only
- **Q18 — Повтор create после потерянного ответа и параллельные retries.** Один ID/одна заявка/одно событие на operation key; другой key — отдельная намеренная заявка
- **Q19 — Ключ операции другого пользователя, тот же key с другим payload.** Нет доступа к чужому результату; конфликт payload обрабатывается по контракту
- **Q20 — Два staff сохраняют одну версию через UI и прямой API.** Первый accepted, второй получает явный конфликт; draft не потерян; обход expected_version закрыт
- **Q21 — Dependency update и воспроизводимость.** Lockfile/audit, format/lint/types/обычный build и нужная регрессия PASS на итоговом SHA
- **Q22 — Restore drill.** Восстановление в отдельную БД; схема/RLS/grants/данные/необходимые Auth/files/config проверены, RPO/RTO измерены
- **Q23 — Ошибка staging и уведомление.** Безопасный код/среда/SHA, без token/PII; алерт получил назначенный человек
- **Q24 — Административный offboarding.** Принятая деактивация сохраняет сервисную историю; каскадное удаление не применяется молча

## Пилот на объекте

- **P00 — Карточка пилота и разрешённые исходные данные приняты.** Указаны реальный объект/здание, участники, язык, допустимые документы, поддержка и границы; нет выдуманных согласований
- **P01 — Создать объект, контракт и здание; повторно войти.** Данные сохранены, связи и версия документа верны
- **P02 — Смена здания и навигация.** Все разделы относятся к выбранному зданию; нет переноса чужого контекста в форму
- **P03 — Два объекта/два клиента, списки/поиск/count/download/API.** Ни одного чужого результата и файла; UI и прямой API дают одинаковую область прав
- **P04 — Подмена site_id/building_id/equipment_id.** БД отклоняет несогласованную цепочку родителей
- **P05 — Членство в объекте без права на внутренний контракт.** Нет доступа к содержимому/пути/download; публикация только уполномоченным сотрудником
- **P06 — Новая версия файла и отказ загрузки.** Предыдущая версия/авторство сохранены; не остаётся ложной успешной карточки
- **P07 — Отзыв членства, старый JWT и уже выданная ссылка.** Новые запросы запрещены; остаточный TTL ссылки соответствует принятой политике
- **P08 — Backfill прежних заявок, одинаковые site-названия.** Сохранены автор/результат/события/приватность; нет автоматического объединения объектов
- **P09 — Данных больше API response limit.** Все разрешённые записи достижимы через страницы; фильтры/count полны, сортировка стабильна
- **P10 — Длинные тексты, 360/390/768/1440 px, клавиатура, 200%.** Нет потери действий/фокуса/ввода, доступные подписи и ошибки; реальные Android/iOS проверены
- **P11 — Плохая сеть/timeout/повтор/refresh/logout.** Нет дублей и ложного успеха, контекст и draft сохранены согласно контракту
- **P12 — Заказчик проходит реальный сквозной сценарий.** Разрешённый контракт → здание → заявка → результат → история принят представителем

Будущие OP07–OP13: принадлежность оборудования зданию и история перемещений; версии регламентов/графиков; таймзона/конец месяца/пропуск/пауза; одно задание на период при параллельной генерации; checklist/исполнитель/результат; отдельная заявка из дефекта. Завершение проверки не означает устранение.

R01 regression: отказ logout сохраняет сессию, retry делает серверный запрос и отзывает refresh token; отсутствующая сессия не подтверждает success. R02 regression: неизвестные tables/schema и небезопасные Auth/PKCE данные отказывают до replacement, fixture rows остаются.

Каждый результат записывается с датой, средой и SHA. P1 по доступу/данным/recovery/восстановлению блокирует выпуск; P2 требует явного решения с влиянием. Ready/пустой advisor список не заменяет сценарии. Разрушительные проверки production запрещены. [Допуск выпуска](RELEASE_ROLLBACK_RUNBOOK.md).
